# ДЗ9 · Этап 5 · Подготовка пост-хок прогона

Дарья Бабикова, LLM4Rec, ВШЭ. 27 ноября 2026 года.

## Что проверяем

Отдельная строка **post-hoc «U1 + схема ДЗ8»** использует тот же U1 и те же 100 пользователей, но возвращает `source_cbf_rank` и точную исходную инструкцию ДЗ8. Решение принято после диагностики формата без июньских меток и зафиксировано в [DECISIONS.md](DECISIONS.md) до запуска. Основной зарегистрированный результат с 97/100 fallback сохранён. В `main_g` поле ранга совпадает с определением LambdaMART, поэтому асимметрии по наличию этого поля для пост-хок строки нет.

## Проверки бандла

| Проверка | Итог |
| --- | --- |
| `main_g` | 100 промптов в порядке исходного протокола |
| `ablation_g_seed0`, `ablation_g_seed1`, `ablation_g_seed2` | По 100 промптов, те же блоки и доноры, что на этапе 3 |
| Первые 20 `main_g` против условия G | 20/20 побайтовых совпадений |
| Самоназначения в абляции | 0 из 300 |
| Неизменяемые поля кандидатов и порядок против `main_g` | 300/300 побайтовых совпадений после исключения четырёх подменяемых полей |
| Ранги из истории донора | Сверены все 6000 значений с CBF50 доноров, 3601 отметка `null` за пределами CBF50 |

CBF-баллы доноров пересчитаны только по данным до cutoff. Сохранённый порядок CBF50 использован для разрешения численных равенств после сверки баллов по позициям с пересчитанным списком. `source_cbf_score`, `past_buy_count` и `last_buy_age_days` независимо пересчитаны по истории тех же доноров и сверены с исходной абляцией этапа 3. Профиль, состав и порядок U1 сохранены. Бандл не содержит CSV или меток. SHA‑256 `summary.json` и `predictions.csv` этапа 4 совпали с прежними.

## Запуск в Colab

1. Создай `MyDrive/HW9_Ranker/posthoc/` и помести туда `bundle_posthoc.zip`. Открой `notebooks/hw9_posthoc_gpu.ipynb` в Colab и выбери T4. CSV для запуска не нужны.
2. Запусти ячейки 1–3. Они подключат Drive, сверят SHA‑256 архива, его файлов и промптов и проверят веса Qwen/Qwen3‑1.7B ревизии `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`. Блокнот использует `float16`, greedy, thinking off, `max_new_tokens=256` и те же закреплённые зависимости, что на этапе 3.
3. Запусти ячейку 4. Она сохранит сырые ответы в четырёх JSONL под `posthoc/posthoc_results/`. При прерывании сохрани эту папку и снова выполни ячейки 1–4 с тем же архивом и окружением. Записанные ID пропускаются. Запускай один экземпляр блокнота на папку.
4. Ячейка 5 скачает `hw9_posthoc_colab_results.zip`. Распакуй содержимое в локальную папку `hw9_ranker/outputs/stage5/colab_results/`. Блокнот не разбирает ответы, не считает nDCG и не запускает ранкер преподавателя.

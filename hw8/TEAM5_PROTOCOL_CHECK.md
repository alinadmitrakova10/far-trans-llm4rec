## Какие файлы нужны для сверки отдельного прогона

Если появится новый baseline-прогон, собрать из **одного и того же запуска**:

1. `protocol.json`, `metrics.json`, `contexts.jsonl` целиком, а не скриншоты или округлённую таблицу.
2. `predictions.csv` и `per_user.csv`, чтобы проверить выдачи, метки и расчёт агрегатов при совпадающем протоколе.
3. Полный 40-символьный **commit SHA репозитория, из которого запускался её код**, URL репозитория и сведения о незакоммиченных изменениях во время запуска. Если её starter лежит вне Git — также источник/commit преподавательского starter и точный SHA-256 реально использованного `starter.py`. Наш SHA-256 starter: `bf6b7c0b0b271e057e82547eff23738e65bc9cdbb626703d13d1801ff99aab80`.
4. Точную команду/параметры запуска, `runtime.json` или описание границ замера, среду/версии и устройство. Разное оборудование или runtime не должны выдавать за одинаковую скорость методов.
5. Подтверждение, какие именно результаты используются как общие baseline. Совпадение файлов само по себе не доказывает согласование метода всеми участницами.

## Что сравнить

1. **Полный JSON протокола**, а не только короткий hash: корректность пересчёта `protocol_hash`, SHA-256 четырёх исходных CSV, cutoff `2021-06-01`, end exclusive `2021-07-01`, exact-duplicate policy, исключение отрицательных transactionID, warm cohort, отсутствие exclude-seen, candidate_count=50, k=10 (длина выдачи). Наш полный hash: `50efd4aeb415ba6f0c66dd0793a7c2033cdc32a42b86b58eebbca3e81eaf3417`.
2. **Точный список и порядок 100 user ID**, eligible catalog и eligible IDs каждого пользователя, пустую truth как ноль. Пользователей с непустой truth должно быть 11 при тех же данных и правилах; нельзя отбирать пользователей по наличию будущих покупок.
3. **Все 100 contexts** как JSON-объекты: история/counts, as-of метаданные, порядок кандидатов и eligible IDs. Для Ranker одинаковые settings без одинаковых candidate IDs и их порядка недостаточны. Сравнение только JSON-текста может отличаться из-за CRLF/LF: при разных переводах строк сравнивать распарсенные значения; массивы не пересортировывать.
4. **Версию фактически исполненного starter**: protocol hash включает параметры/данные, но не хеш самого Python-кода. Поэтому одинакового protocol hash недостаточно для подтверждения идентичности реализации.
5. **Четыре baseline, Top-10 и per-user метрики**: одинаковые user/method пары, 10 уникальных допустимых ISIN, relevant_count, полный nDCG и оба агрегата. Не ограничиваться четырьмя знаками. Уточнить ошибки/fallback и измеряемый runtime scope. Время может отличаться на другом устройстве при полностью одинаковых рекомендациях.

Если найдены различия, сначала перечислить конкретные поля/пользователей/кандидатов или версии кода и объяснить причину; не менять молча нашу когорту, параметры или июньскую truth. После технической сверки зафиксировать, кто использовал какие baseline-артефакты. При расхождении общей выборки итоговую оценку обсуждать отдельно, без подбора параметров по июню.

## Нативная OpenCode-сессия для сдачи

Нативный JSON Алины сохранён локально и проверен. Для повторного экспорта в терминале с установленным OpenCode CLI выполните `opencode --version`, `opencode export --help`, затем `opencode session list`. Найдите ID нужной сессии этого проекта. **Нативный JSON** выгружается командой `opencode export <sessionID>`; `/export` в TUI может давать Markdown и не заменяет нативный JSON.

Для Windows PowerShell 5.1 после выбора реального ID (замените `ses_...`):

```powershell
Test-Path -LiteralPath "C:\Users\dmitr\Desktop\dz_jin\hw7"
New-Item -ItemType Directory -Force -Path "C:\Users\dmitr\Desktop\dz_jin\hw7\exports"
$sessionId = 'ses_...'
$target = 'C:\Users\dmitr\Desktop\dz_jin\hw7\exports\alina_hw8_opencode_session.json'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$native = & opencode export $sessionId
if ($LASTEXITCODE -ne 0) { throw 'OpenCode export failed' }
$text = $native -join "`n"
$parsed = $text | ConvertFrom-Json
if ($parsed.info.id -ne $sessionId -or -not $parsed.messages) { throw 'Wrong or incomplete session export' }
[System.IO.File]::WriteAllText($target, $text, [System.Text.UTF8Encoding]::new($false))
```

Это сохраняет stdout нативного экспорта как UTF-8 без преобразования структуры JSON. Убедитесь, что в файле есть сообщения и части tool calls с результатами/patches, а не только сведения о сессии. Экспортируйте после завершения текущей работы; при нескольких OpenCode-сессиях сохраните каждую отдельно и перечислите ID/охват. Нативный JSON содержит историю OpenCode. Использование других инструментов отражается в AI Usage Disclosure. Для сдачи укажите фактические версии инструментов/моделей и личный вклад. Каталог `exports/` исключён из Git.

Формат `export [sessionID]` и структура `{info, messages: [{info, parts}]}` проверены по [реализации OpenCode v1.0.100](https://github.com/anomalyco/opencode/blob/v1.0.100/packages/opencode/src/cli/cmd/export.ts). Сверьте `--version` и `export --help` своей установки; её версию и доступный ID эта среда не определила.

При подготовке исходного handoff команда `opencode` не была доступна в терминале. Если команда недоступна в вашем терминале, используйте полный путь к CLI executable вашей установки и сначала проверьте его `export --help`; конкретный ID сессии не угадывается.

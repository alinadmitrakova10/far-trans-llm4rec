## Что сравнить

1. **Полный JSON протокола**, а не только короткий hash: корректность пересчёта `protocol_hash`, SHA-256 четырёх исходных CSV, cutoff `2021-06-01`, end exclusive `2021-07-01`, exact-duplicate policy, исключение отрицательных transactionID, warm cohort, отсутствие exclude-seen, candidate_count=50, k=10 (длина выдачи). Наш полный hash: `50efd4aeb415ba6f0c66dd0793a7c2033cdc32a42b86b58eebbca3e81eaf3417`.
2. **Точный список и порядок 100 user ID**, eligible catalog и eligible IDs каждого пользователя, пустую truth как ноль. Пользователей с непустой truth должно быть 11 при тех же данных и правилах; нельзя отбирать пользователей по наличию будущих покупок.
3. **Все 100 contexts** как JSON-объекты: история/counts, as-of метаданные, порядок кандидатов и eligible IDs. Для Ranker одинаковые settings без одинаковых candidate IDs и их порядка недостаточны. Сравнение только JSON-текста может отличаться из-за CRLF/LF: при разных переводах строк сравнивать распарсенные значения; массивы не пересортировывать.
4. **Версию фактически исполненного starter**: protocol hash включает параметры/данные, но не хеш самого Python-кода. Поэтому одинакового protocol hash недостаточно для подтверждения идентичности реализации.
5. **Четыре baseline, Top-10 и per-user метрики**: одинаковые user/method пары, 10 уникальных допустимых ISIN, relevant_count, полный nDCG и оба агрегата. Не ограничиваться четырьмя знаками. Уточнить ошибки/fallback и измеряемый runtime scope. Время может отличаться на другом устройстве при полностью одинаковых рекомендациях.

Если найдены различия, сначала перечислить конкретные поля/пользователей/кандидатов или версии кода и объяснить причину; не менять молча нашу когорту, параметры или июньскую truth. После технического совпадения нужно отдельно подтвердить с Ульяной использование конкретных baseline-артефактов как общих и корректно указать вклад. При расхождении общей выборки итоговую оценку обсуждать отдельно, без подбора параметров по июню.

## Нативная OpenCode-сессия для сдачи

В пользовательском терминале с установленным OpenCode CLI выполните `opencode --version`, `opencode export --help`, затем `opencode session list`. Найдите ID нужной сессии этого проекта. **Нативный JSON** выгружается командой `opencode export <sessionID>`; `/export` в TUI может давать Markdown и не заменяет нативный JSON.

Для Windows PowerShell 5.1 после выбора реального ID (замените `ses_...`):

```powershell
Test-Path -LiteralPath "C:\Users\dmitr\Desktop\dz_jin\hw7"
New-Item -ItemType Directory -Force -Path "C:\Users\dmitr\Desktop\dz_jin\hw7\exports"
$sessionId = 'ses_...'
$target = 'C:\Users\dmitr\Desktop\dz_jin\hw7\exports\alina_hw8_opencode_session.json'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$native = & opencode export $sessionId
if ($LASTEXITCODE -ne 0) { throw 'OpenCode export failed' }
$text = $native -join "`n"
$parsed = $text | ConvertFrom-Json
if ($parsed.info.id -ne $sessionId -or -not $parsed.messages) { throw 'Wrong or incomplete session export' }
[System.IO.File]::WriteAllText($target, $text, [System.Text.UTF8Encoding]::new($false))
```

Это сохраняет stdout нативного экспорта как UTF-8 без преобразования структуры JSON. Убедитесь, что в файле есть сообщения и части tool calls с результатами/patches, а не только сведения о сессии. Экспортируйте после завершения текущей работы; при нескольких OpenCode-сессиях сохраните каждую отдельно и перечислите ID/охват. Действия Codex в Colab требуют отдельного экспорта Codex; их нельзя выдавать за tool calls OpenCode. Для сдачи укажите фактические версии инструментов/моделей и личный вклад. Каталог `exports/` исключён из Git.

Формат `export [sessionID]` и структура `{info, messages: [{info, parts}]}` проверены по [реализации OpenCode v1.0.100](https://github.com/anomalyco/opencode/blob/v1.0.100/packages/opencode/src/cli/cmd/export.ts). Сверьте `--version` и `export --help` своей установки; её версию и доступный ID эта среда не определила.

В терминале этой OpenCode-сессии executable `opencode` не обнаружен на PATH; сам экспорт здесь не создан. Если команда недоступна в вашем терминале, используйте полный путь к CLI executable вашей установки и сначала проверьте его `export --help`; конкретный ID сессии не угадывается.
